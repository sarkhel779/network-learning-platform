<h2 id="inspect-udp-evidence">Inspect UDP evidence</h2>

Use a `udp` capture filter, then narrow to the expected source and destination ports. Compare the UDP length and checksum, the application request, any response, and any related ICMP error. On Linux, inspect listening sockets with `ss -ulpen`; on Windows, use `Get-NetUDPEndpoint` or `netstat -ano`.

<WiresharkCheck displayFilter="udp || icmp">Capture one UDP request. Record the endpoint tuple, datagram length, matching application evidence, a response or ICMP message if present, and what remains unknown if there is silence.</WiresharkCheck>

<h2 id="guided-udp-diagnosis">Guided UDP diagnosis</h2>

An absent reply is only absence of observed reply evidence. Check whether the request reached the host, a matching socket existed, the application processed it, a response left, and the response had a return path.

<InterviewScenario title="A DNS query gets no answer">Explain why UDP silence does not prove that port 53 is closed. Name one capture or log at each end that would narrow the cause.</InterviewScenario>

<h2 id="troubleshoot-udp">Troubleshoot UDP methodically</h2>

1. Confirm the address, transport protocol, source port, and destination port.
2. Check the receiving socket and application logs.
3. Capture the request, response, and any ICMP error in both directions.
4. Check firewall policy and forward and return routes.
5. Compare with a known-good request before deciding what silence means.
