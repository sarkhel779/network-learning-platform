<h2 id="what-is-a-hub">What is a hub?</h2>

A **hub** is a simple central device that connects several hosts on one shared Ethernet network. Each host uses a cable connected to one of the hub's ports.

Think back to the hosts in the previous lesson: their Ethernet adapters need somewhere to connect. A hub provides several cable sockets, called **ports**, so those hosts can join one local network. It is a network hub, not a USB hub.

A hub works with the signal arriving on a port. It does not identify the intended recipient and it does not choose the best outgoing port.

<h2 id="how-a-hub-handles-a-signal">How a hub handles a signal</h2>

When a signal enters one port, the hub repeats that signal through **every other active port**. If a laptop is connected to Port 1 and three other hosts use Ports 2, 3, and 4, all three hosts receive a copy.

The hub behaves like a loudspeaker in a room: it repeats what it receives so everyone connected can hear it. The receiving hosts determine whether the information is useful to them.

This is why a hub is called a **multiport repeater**: *multiport* means several ports, and *repeater* means it repeats incoming signals. It operates at the **Physical Layer (Layer 1)**, rather than reading destination addresses to decide where to send a frame.

For a message addressed only to the server, all three receiving hosts see the signal. Their network adapters examine the frame: the server accepts it, while the workstation and printer normally discard it because it is not addressed to them. **The receiving hosts make that decision—not the hub.**

<h2 id="shared-network-behaviour">Shared network behaviour</h2>

Every device connected to the hub shares the same communication space and the same available capacity. This is called **shared bandwidth**: more active devices must share the network rather than receiving a separate connection of their own.

If two hosts transmit at the same time, their signals can interfere with one another. This is called a **collision**. For this introductory lesson, remember only that a hub creates one shared environment in which simultaneous transmissions can conflict.

<HubSharedMediumOverview />

Hub-based Ethernet uses **half-duplex** communication: only one host can transmit successfully at a time, and a host cannot send and receive simultaneously. The other hosts receive while that one host sends. We will study collision detection and recovery later.

<h2 id="why-switches-replaced-hubs">Why switches replaced hubs</h2>

Modern Ethernet networks normally use switches instead of hubs. A hub repeats a signal everywhere, while a switch can be more selective about where it sends network traffic.

That difference makes switches more efficient for modern local networks. How switches make their decisions will be taught later; here, the important distinction is **hub: repeat to every other port**.
