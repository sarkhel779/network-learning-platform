<h2 id="troubleshoot-the-first-failed-hop">Troubleshoot the first failed hop</h2>

Work from the source outward and record evidence instead of restarting every device:

1. Confirm the host has an address, prefix, gateway and usable interface.
2. Confirm the host selects the expected route.
3. Check whether ARP resolves the gateway.
4. Verify the request leaves the host and reaches the switch/router boundary.
5. Verify the router has a route and creates the next-link frame.
6. Look for the request at the server and then follow the reply in reverse.

<InterviewScenario prompt="The PC repeatedly broadcasts ARP for its gateway but receives no reply. What has failed, and what has not yet been tested?">
The failure is still on the local next-hop resolution path. Check the PC interface and VLAN, switch forwarding, the gateway interface state and address, and whether the devices share the intended broadcast domain. Remote routing, the server, and the return path have not yet been tested because the first unicast frame was never created.
</InterviewScenario>
