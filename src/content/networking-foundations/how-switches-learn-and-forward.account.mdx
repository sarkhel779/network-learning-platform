<h2 id="read-mac-table-evidence" tabIndex={-1}>Read MAC-table evidence</h2>

<a className="primary-link" href="#diagnose-switching-behaviour">I know this—proceed to advanced</a>

A MAC table is evidence about learned Layer 2 locations. Read the VLAN or forwarding context,
MAC address, learned interface and entry freshness together. A single entry does not prove that
the endpoint has a correct IP address, that return traffic works, or that its application is healthy.

<h2 id="diagnose-switching-behaviour">Diagnose switching behaviour</h2>

Use the same evidence sequence every time:

1. Define the affected source, destination, direction and Layer 2 scope.
2. Verify link and interface state before interpreting the MAC table.
3. Identify ingress and read the frame's source and destination MAC addresses.
4. Confirm whether the source entry was learned or refreshed.
5. Classify the destination as known unicast, unknown unicast or broadcast.
6. Predict eligible egress interfaces, excluding ingress.
7. Repeat the same traffic and compare the new table and forwarding result.

Common mistakes include clearing the entire table before collecting evidence, calling every flooded
frame a broadcast, assuming an aged entry proves failure, and treating a learned MAC as proof that
the application works. A physical link failure must be repaired before MAC-table changes can help.

<InterviewScenario prompt="The first frame to a server is seen on three access ports, but later frames use only one. Is the switch malfunctioning?">
Not necessarily. The first destination may have been unknown, so the switch flooded eligible ports.
A reply taught the server's source location, allowing later known-unicast forwarding. Verify the
destination bit pattern, table timestamps, VLAN and capture position before concluding there is a loop.
</InterviewScenario>

<InterviewScenario prompt="A user's MAC address changes from Gi0/2 to Gi0/3. What would you verify before treating it as an attack?">
Confirm the endpoint identity, recent physical move, wireless or downstream bridging path, timestamps,
VLAN context and repeated source frames. Source learning refreshes a legitimate moved host. Rapid
alternation between distant interfaces can be suspicious, but one updated entry is not sufficient proof.
</InterviewScenario>
