<h2 id="why-routing-protocols-exist">Why routing protocols exist</h2>

A static route works until the network changes: a link fails, a new subnet appears, or traffic needs to shift to a healthier path. Reconfiguring every router by hand does not scale past a handful of routers and cannot react in real time. A routing protocol lets routers exchange reachability information with each other and recompute forwarding automatically when the topology changes.

<h2 id="static-vs-dynamic-routing">Static vs. dynamic routing</h2>

A **static route** is entered by an administrator and never changes until someone edits it; it is predictable and adds no protocol overhead, but it does not adapt to a failed link or a new destination on its own. A **dynamic route** is learned through a routing protocol; it adapts automatically but adds control-plane traffic, memory and CPU cost, and its own failure modes, since a misconfigured or compromised neighbor can inject bad routes. Production networks commonly combine both: static routes for a single well-known edge, dynamic protocols wherever topology or scale demands automatic adaptation.

<h2 id="distance-vector-vs-link-state">Distance-vector vs. link-state</h2>

A **distance-vector** protocol tells each neighbor only "here is my best distance to each destination"; a router trusts what its neighbors report and never sees the full topology. It is simple to run but converges slowly and is prone to routing loops, which is why distance-vector protocols need loop-prevention mechanisms such as split horizon and route poisoning.

A **link-state** protocol instead floods each router's own list of directly connected links to every other router in its area, so every router builds an identical map of the topology and independently computes the shortest path with an algorithm such as Dijkstra's. Link-state protocols converge faster and avoid most routing loops, at the cost of more memory and CPU on each router.

<h2 id="rip-basics">RIP basics</h2>

**RIP** (Routing Information Protocol) is a distance-vector protocol that measures distance in **hop count**, with 15 hops as the maximum usable metric and 16 meaning "unreachable." Routers advertise their full routing table to neighbors on a fixed timer, classically every 30 seconds, and a route ages out if it is not reheard within a hold-down window. RIP's simplicity made it an early standard, but hop count ignores bandwidth and latency entirely, and its slow, periodic convergence is a poor fit for modern networks — most production networks now use RIP only in small or legacy deployments.

<h2 id="ospf-basics">OSPF basics</h2>

**OSPF** (Open Shortest Path First) is a link-state protocol that measures cost as an inverse function of interface bandwidth by default, so faster links are preferred. Routers are organized into **areas**; Area 0, the backbone, must exist and every other area typically attaches to it, which limits how far a single topology change has to propagate and keeps each link-state database a manageable size. Within an area, every router holds an identical link-state database and computes its own shortest-path tree, so convergence after a change is fast compared with RIP.

<h2 id="bgp-basics">BGP basics</h2>

**BGP** (Border Gateway Protocol) is the routing protocol that holds the public Internet together, and it works differently from RIP or OSPF: instead of hop count or link cost, BGP is a **path-vector** protocol that selects routes using a rich set of path attributes, including AS-path length, local preference, and origin, and is built around policy — an organization decides which routes it accepts, prefers, and announces, not just which path is numerically shortest. BGP runs between **autonomous systems**, independently administered networks each identified by an AS number; two BGP routers exchanging routes are called **peers**, and the relationship can be **eBGP**, between different autonomous systems, or **iBGP**, within the same one. BGP scales to hold the entire Internet's routing table precisely because it prioritizes policy and stability over fast recalculation, a property that also makes it comparatively slow to converge after a failure.

<h2 id="choosing-a-routing-protocol">Choosing a routing protocol</h2>

The right protocol depends on scope and control, not on which is "best": RIP is rarely a first choice today, OSPF suits a single organization that wants fast convergence and full visibility into its own topology, EIGRP suits an all-Cisco enterprise that wants OSPF-like convergence with simpler configuration, and BGP is what connects one autonomous network to another. Most large networks run an interior protocol like OSPF internally and use BGP only at their boundary with other networks.
