<h2 id="what-makes-a-device-a-host">What makes a device a host?</h2>

In lesson 1, your laptop created a print job and the printer received it. Both were end devices. In networking, we call these devices **hosts**.

A **host** is an end device that participates in network communication. It is a source or destination of data, rather than a device whose job is to connect other devices or networks.

The shape or price of a device does not decide whether it is a host. Its participation in the network does. **A printer with a network interface is a host.**

<h2 id="network-interfaces">Network interfaces</h2>

A host joins a network through a **network interface**: the hardware and software connection point it uses to send and receive network data. Think of it as the host's doorway to the network.

### What is a network interface card (NIC)?

A **network interface card (NIC)**, also called a **network adapter**, is the hardware that gives a host a physical connection to a network. Despite the name, it does not have to be a separate card: it can be built into a laptop or phone, installed as an expansion card, or connected as a USB adapter.

**What does it do?** It sends the host's network data onto a connection and receives incoming data for the host to process. An Ethernet adapter uses a cable; a Wi-Fi adapter uses radio signals. These connections let the host use services such as websites, shared files, and network printing.

**Where might you use one?** A desktop may use a built-in Ethernet adapter to connect to a switch. A laptop may use its built-in Wi-Fi adapter to connect to an access point, or a USB Ethernet adapter when it has no Ethernet socket.

The **adapter** is the hardware; the **interface** is the connection point the host uses. We will cover its addressing and detailed data handling in later lessons.

<h2 id="clients-and-servers">Clients and servers</h2>

Now that a host is connected, what does it do? Suppose you open a website. Your browser asks for a page, and a web server application provides it.

A **client application** asks for a service. A **server application** provides that service and responds.

<ClientServerOverview />

Client and server describe what applications are doing in one conversation. They are not permanent hardware categories: a large computer is not automatically a server, and a phone is not always only a client.

<h2 id="one-host-more-than-one-role">One host, more than one role</h2>

One host can run several applications at once. **The same computer can run a client application and serve a file to another device.** Its role depends on what each application is doing in that conversation.

In the file-sharing player, Computer A first requests a file from Computer B. The next conversation reverses those roles. The computers did not change type; their applications changed jobs.
