<h2 id="inspect-ipv6-evidence">Inspect IPv6 evidence</h2>

On **Windows**, use `ipconfig /all`, `Get-NetIPAddress -AddressFamily IPv6`, `Get-NetRoute -AddressFamily IPv6`, and `Get-NetNeighbor -AddressFamily IPv6`. On **Linux**, use `ip -6 address`, `ip -6 route`, and `ip -6 neighbour`. In Wireshark, start broadly with `ipv6`, then isolate Neighbor Discovery with `icmpv6` or message filters such as `icmpv6.type == 135`.

<WiresharkCheck displayFilter="icmpv6">Find an NS/NA exchange. Compare the solicited-node multicast destination, ICMPv6 target address, Ethernet destination, and the neighbour-cache result.</WiresharkCheck>

<h2 id="practice-ipv6">Practise IPv6 interpretation</h2>

For each supplied address, expand all eight hextets, apply canonical shortening, classify its type and scope, split the prefix at the stated length, and derive the solicited-node multicast address. Then decide whether the first hop targets the neighbour or the default router.

<h2 id="troubleshoot-ipv6">Troubleshoot IPv6 methodically</h2>

1. Confirm the interface has a usable link-local address and is not stuck tentative after DAD.
2. Verify the prefix length and on-link route instead of judging by similar-looking text.
3. Check Router Advertisements for prefix, lifetime, and default-router information.
4. Inspect the neighbour cache and NS/NA exchange for the selected next hop.
5. Check ICMPv6 filtering; blocking essential control messages can break IPv6 even when addresses look correct.
