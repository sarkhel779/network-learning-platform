<h2 id="identify-device-roles">Identify device roles</h2>

Use **I know this—proceed to advanced** to move directly to the first troubleshooting scenario below.

For each symptom, name the role before the box:

1. A laptop cannot associate with the SSID: begin with the client radio and access-point role.
2. Wi-Fi association works but the host has no usable route: inspect addressing, DHCP evidence, and the router-facing path.
3. The ONT reports loss of optical signal: investigate the fibre access circuit and provider handoff before changing firewall policy.
4. A bridged modem works with one router but not after adding another: confirm which device owns the WAN address and avoid accidental double routing.

<h2 id="diagnose-edge-failures">Diagnose edge failures</h2>

Follow the boundary in order: client link → access point → LAN → router → firewall decision → modem or ONT → provider handoff. Record the last working interface and the first failing interface.

Do not reset every device at once. A Wi-Fi failure, missing route, denied session, optical loss alarm, and provider outage belong to different fault domains even when the same enclosure exposes their status lights.

<InterviewScenario prompt="A laptop joins Wi-Fi and reaches the gateway, but an Internet connection fails. How would you narrow the fault domain?">
The access-point path and local gateway are already working. Confirm the router has a usable WAN route, then distinguish a firewall denial from a modem or ONT link problem and an upstream provider failure. Use interface status, routing evidence, firewall session or deny evidence, and provider-link indicators in that order.
</InterviewScenario>
