<h2 id="inspect-subnet-evidence">Inspect subnet evidence</h2>

On **Windows**, compare `ipconfig`, `Get-NetIPAddress`, and `Get-NetRoute`. On **Linux**, compare `ip address` and `ip route`. Record the active interface, address, prefix, derived network, and default route. A displayed address alone does not prove that its mask or gateway is correct.

<h2 id="practice-subnet-planning">Practice subnet planning</h2>

For each `/24` through `/30` example, write the mask, block size, network address, broadcast address, usable range, and capacity before checking the result. Always verify that the chosen host is neither the traditional network nor broadcast address.

<h2 id="troubleshoot-subnetting">Troubleshoot subnetting methodically</h2>

1. Confirm the address and prefix on the interface carrying traffic.
2. Calculate each endpoint's network address independently.
3. Check for an invalid network or broadcast host assignment.
4. Compare the intended ranges for overlap or unintended gaps.
5. Verify that local-versus-gateway behavior matches the calculated boundary.
