<h2 id="troubleshooting-interview">Troubleshooting and interview scenarios</h2>

Work upward from link, to local delivery, to IP path, transport reachability, and application
behavior. A successful lower-layer check narrows the next question; it does not prove every
higher layer is healthy.

<InterviewScenario prompt="A laptop has a link light but cannot open an internal website. How would you organize your first checks?">
  <ol>
    <li>Verify the interface is enabled and confirm the physical or wireless link is stable.</li>
    <li>Check the laptop's IP address, subnet mask, DNS settings, and default gateway.</li>
    <li>Test local delivery, followed by gateway and destination IP reachability.</li>
    <li>Verify that the required TCP or UDP port is reachable.</li>
    <li>Inspect DNS resolution and the website's HTTP, HTTPS, or TLS response.</li>
    <li>State the evidence found at each layer; a link light alone does not prove HTTP is healthy.</li>
  </ol>
</InterviewScenario>

<InterviewScenario prompt="How would you explain encapsulation and compare OSI with TCP/IP in an interview?">
  <ol>
    <li>Begin with application data, such as an HTTP request created by a browser.</li>
    <li>Explain that transport adds TCP or UDP information, including port numbers.</li>
    <li>Explain that the Internet layer adds IP addressing and the local link adds frame information.</li>
    <li>Describe the receiver removing and interpreting that information in reverse order.</li>
    <li>Compare the models: OSI separates seven conceptual layers, while TCP/IP groups them into four practical layers.</li>
    <li>Anchor the explanation to HTTP, TCP or UDP, IPv4, and Ethernet or Wi-Fi instead of only reciting layer names.</li>
  </ol>
</InterviewScenario>

You can now connect a visible protocol field to a responsibility: application data serves the
user, transport identifies a conversation, IP identifies a path, and Network Access carries a
frame over one local link. Later lessons will examine DNS, TCP and UDP, routing, switching, and
firewall policy in greater depth.
