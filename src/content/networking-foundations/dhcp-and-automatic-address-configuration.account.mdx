<h2 id="inspect-dhcp-evidence">Inspect DHCP evidence</h2>

Capture with `bootp` or `dhcp`; narrow a transaction with `bootp.xid == 0x1234abcd`. For each packet record message type, source/destination MAC and IPv4 addresses, UDP ports, `xid`, `secs`, broadcast flag, `ciaddr`, `yiaddr`, `siaddr`, `giaddr`, server identifier, requested address, lease timers, and relay information. Compare the capture with server lease logs and relay counters rather than trusting one screen alone.

<WiresharkCheck displayFilter="bootp">Capture one direct or relayed DHCP exchange. Prove its message order, delivery mode, transaction identity, selected address or failure point, and the exact field supporting each conclusion.</WiresharkCheck>

<h2 id="guided-dora-diagnosis">Guided direct-DORA diagnosis</h2>

Start with the last state transition actually observed. Repeated Discover with **no offer** narrows the failure to server reachability, server policy, **address-pool exhaustion**, filtering, or the return path; it does not prove the server is down. If an Offer arrives but no Request follows, investigate client selection and competing offers. A NAK is explicit rejection, while silence remains ambiguous.

<InterviewScenario title="Discover repeats but no Offer returns">Identify the client broadcast, UDP 68/67, transaction ID, scope capacity, server logs, security policy, and a known-good client comparison. State what the capture proves and what still needs evidence.</InterviewScenario>

<h2 id="guided-relay-diagnosis">Guided relay/helper-address diagnosis</h2>

Prove all four legs. A **missing helper address** prevents a local broadcast from becoming routed relay traffic. A **helper on the wrong interface** may never receive the client broadcast. If the **scope does not match `giaddr`**, the server cannot select the intended client subnet. Verify that `giaddr`, relay source, hop count, and any Option 82 identity agree with the topology.

<InterviewScenario title="The local VLAN sees Discover, but the server sees nothing">Locate the client-facing layer-3 interface, helper configuration, route, ACL, relay/server UDP 67-to-67 path, and server-facing capture. Explain why a working helper on another interface is not sufficient.</InterviewScenario>

<h2 id="troubleshoot-dhcp">Troubleshoot DHCP methodically</h2>

1. Confirm client link/VLAN membership and the expected IPv4 scope.
2. Capture the client broadcast and confirm UDP 68 to 67.
3. For a remote server, verify helper placement, `giaddr`, and both UDP 67-to-67 relay legs.
4. Check pool availability, exclusions, reservations, and policy for **address-pool exhaustion**.
5. Test ACL, firewall, or security controls for **blocked UDP 67/68** in both directions.
6. Separate a **missing helper address**, **helper on the wrong interface**, and **scope does not match `giaddr`** with interface and server evidence.
7. Treat **no offer** as an observation, then locate the first missing leg.
